# kanz-catalog — كتالوج كنز

مستودع بيجمع تلقائيًا تطبيقات أندرويد **مفتوحة المصدر** من GitHub (وGitLab وCodeberg) وبيطلّع كتالوج صغير مضغوط لتطبيق **كنز**.
GitHub Actions بيشغّل الـ crawler كل 30 دقيقة مجانًا. مفيش سيرفر.

## خطوات الرفع (مرة واحدة)
1. على GitHub اعمل مستودع جديد **Public** اسمه `kanz-catalog` (بنفس حسابك `ibra8y3-web`).
2. فك الـ zip، وارفع **كل محتوياته** للمستودع (Add file ← Upload files). لازم يظهر فولدر `.github` و `crawler` و `docs` و `data` و `config.json`.
   لو فولدر `.github` ما ظهرش من المتصفح، اعمل clone للمستودع الفاضي، انسخ المحتويات جواه (مع `.github`)، وبعدين commit و push.
3. من Settings ← Actions ← General ← Workflow permissions اختار **Read and write permissions** واحفظ.
4. من تبويب Actions اختار **crawl** ثم **Run workflow** (أول تشغيل ممكن ياخد 20-40 دقيقة، وبعدها بيشتغل لوحده كل 30 دقيقة).
5. **الموقع (GitHub Pages)**: من Settings ← Pages ← Source: **Deploy from a branch** ← Branch: **main** ومجلد **/docs** ← Save. بعد دقيقة الموقع يشتغل على:
   **https://ibra8y3-web.github.io/kanz-catalog/**
   (لو اسم المستودع أو الحساب مختلف: https://اسم-الحساب.github.io/اسم-المستودع/)
6. الموقع والكتالوج والـ APK كلهم في مجلد `docs/`: `index.html` (الموقع)، `kanz.apk` (ملف التطبيق بتاع زرار التحميل)، `app.json` (الإصدار والحجم وSHA-256 اللي بيظهر في الموقع)، و `catalog.json.gz` (الكتالوج). الـ crawler مش بيلمس `index.html` ولا `kanz.apk`.
7. تطبيق كنز بيقرا الكتالوج من نفس المكان بالرابط `https://raw.githubusercontent.com/ibra8y3-web/kanz-catalog/main/docs/` (لو غيّرت الاسم: التطبيق ← ⋮ ← إعدادات متقدّمة). من القايمة ⋮ في التطبيق في زرار "🌐 موقع كنز".

## لما تطلّع نسخة جديدة من التطبيق
استبدل `docs/kanz.apk` بالنسخة الجديدة وعدّل `docs/app.json` (الإصدار والحجم و`sha256`). أمر الـ hash: `sha256sum kanz.apk`. اختياري: ارفع نفس الملف كـ Release على GitHub (Releases ← Draft a new release) لو عايز رابط تاني.

## بيعمل إيه
- **اكتشاف**: بيدور على GitHub بعدة استعلامات (topic:android-app, fdroid, jetpack-compose…) وبعد أول مرة بيعمل بحث تزايدي (اللي اتحدّث من آخر مرة بس). بيقرا كمان كل مشاريع الحسابات في `seed_owners` (الافتراضي `ibra8y3-web`)، وبيدور على GitLab وCodeberg.
- **قواعد القبول** (كلها لازم تتحقق):
  1. ترخيص مفتوح معروف (قائمة `licenses_ok`). بدون ترخيص = مرفوض، إلا حسابات `trusted_owners_allow_no_license` (حسابك) وبتتعلّم "غير محدد".
  2. فيه Release حقيقي فيه ملف `.apk`.
  3. فيه بصمة SHA-256: من GitHub (`digest`) أو بيحسبها الـ crawler بنفسه من الملف. من غير بصمة مش بينشر.
  4. مش مؤرشف، ومش fork (إلا حسابك).
  5. مفيهوش كلمات mod / cracked / patched / premium unlocked… في الاسم أو الوصف أو اسم الملف. ملفات debug/unsigned/test بتتخطى (إلا لحسابك).
- **متابعة الإصدارات**: كل تشغيل بيسأل GitHub عن كل تطبيق متضاف بـ ETag (الردود 304 مش بتستهلك من حد الطلبات).
- **الحفاظ على القديم**: النسخ بتتضاف بس ومبتتمسحش ولا تتبدّل أبدًا. لو نسخة اتشالت من المصدر بتتعلّم `gone`، ولو الملف اتغير بنفس رقم النسخة بنحتفظ بالاتنين وبنعلّم القديم `sup`.
- **التكرار**: نفس الـ SHA-256 عند أكتر من مشروع = المتأخر بيتعلّم `dup` وبيتخفي من التطبيق. نفس الاسم بس ملفات مختلفة = `maybe_dup` (بتظهر ملاحظة).
- **التصنيف**: تلقائي بالكلمات المفتاحية من الـ topics والوصف على نفس أقسام كنز.
- **الإخراج** (في `docs/`): `catalog.json.gz` (كامل) و `delta.json.gz` (آخر 40 تحديث فقط) و `meta.json` (الأحجام والرقم). التطبيق بينزل `meta.json` الأول (صغير جدًا) وبعدين الجزئي لو ينفع.
- **السجل الداخلي**: `data/state.json` (كل التفاصيل + المرفوضين وسبب الرفض).

## تجربة محلية
`python3 tests/test_offline.py` (اختبار منطق بدون إنترنت) ثم `GITHUB_TOKEN=... python3 crawler/crawl.py`.
بدون توكن: حد GitHub 60 طلب/ساعة، يعني تجربة صغيرة بس.

## تعديل القواعد
كله في `config.json` (استعلامات البحث، التراخيص، الكلمات الممنوعة، الحد الأقصى لحجم APK، ميزانية التحميل).
الفلتر آلي ومش بيضمن إن التطبيق آمن 100%. التطبيق بيعرض تحذير "غير مراجَع يدويًا".
